1. Introduction


1.1 Document purpose


This document is intended for current and prospective clients of Euronext Securities Milan.
It provides a comprehensive overview of the management of registered shares through
the use of the Graphical User interface – GUI, part of the IRI platform.

The purpose of this guide is to enable any business user - Custodian, Registrar to use the
IRI platform autonomously: log in, consult reference data, create an IRI, follow its
lifecycle, interpret statuses and rejections, and react to incoming flows.

This document follows a client user manual logic: it describes the main screens, business
workflows, statuses visible in the interface, and the actions expected in standard situations
as well as exception cases.

It was written according to the following principles:

    •  Task-oriented approach ("how do I do X?"), not feature-oriented.
    •   Explicit personas and detailed user journeys.
    •  Glossary and acronyms at the end of the document.
    •  Targeted GUI screenshots for action and control screens.
    •  Numbered step-by-step procedures.
   •  Reference tables for codes, statuses and business rules.


1.2 Target audience


The target audience for this document are:

    •   registrars,
    •   financial intermediaries, and
    •   other users1 of Euronext Securities Milan services, particularly those seeking
      guidance on the use of the GUI interface of the IRI platform.

2. System and service overview


2.1 Platform description


The IRI platform facilitates the communication regarding final investor information
between market participants and registrars and, in some cases (transaction type codes
SA, SB, SC), it also allows the settlement instruction to be initiated on behalf of clients.

The platform can be used in two distinct ways:

    •   File transfer: this method enables users to connect directly to the IRI platform to
      send and receive the various messages: IRI01/05/04/07/02 for market
       participants and IRI02/03/06/07 for registrars. File transfer is restricted to these
        specific message flows.

    •  GUI interface: through the graphical interface, users can manually create the
      messages mentioned above. The GUI also serves as a dashboard, allowing
       consultation and extraction of detailed information, as described in section 2.2
        (e.g., IRI status consultation, reconciliation status, penalties and formal notices
      management).

This user guide provides information on how platform participants can use the GUI and
the functions available to them.

For further details on the Euronext Securities Milan security file transfer connectivity,
please consult the latest version of our Service Description Documents.

2.2 Platform users and roles


The IRI platform is designed to support Euronext Securities Milan participants in the
transmission of information related to final investors and therefore may be used by
different categories of users.

It provides each type of participant with access to the functionalities relevant to their
role. The platform intends to serve the needs of:

    •  Participants: by enabling them to perform all necessary actions related to
       registered investors, from the transmission of IRIs to the consultation of any
       penalties or formal notices applied.

    •  Registrar: by allowing them to keep up to date the registers they manage on
       behalf of issuers and ensuring smooth communication with all custodians.

2.3.1 Issuer & investor CSD services


When Euronext Securities Milan acts as issuer CSD, the GUI, as part of the IRI platform,
supports the following functions:

    •  Exchange of IRI messages between market participants and registrars
    •  Management of reconciliation between IRI messages and settlement instructions
    •   Monitoring of formal notices and penalties

When Euronext Securities Milan acts as investor CSD, the GUI, as part of the IRI
platform, provides the interface between the issuer‑CSD environment, where the
registrar is located, and participants operating through Euronext Securities Milan. In this
context, it supports:

   •  Exchange and conversion of IRI messages into the formats required by the issuer
     CSD
   •  Display of reconciliation results performed at issuer‑CSD level
   •  Display of penalties and formal notices attributed to Euronext Securities Milan
       participants.

4. Navigating the platform


4.1 Interface overview


The IRI platform interface is designed to offer users a clear, streamlined workspace
where all key functionalities navigation, filtering, consultation creating and modification
details are accessible from a single consistent layout. The interface combines a global
monitoring view with the ability to drill down into specific IRIs, ensuring that users can
quickly locate, review and manage all relevant information. The screen is divided into
distinct functional areas that structure how users interact with the platform.

The general interface layout provides users with a clear and structured workspace that
centralizes all navigation, filtering and consultation features needed to operate within the
IRI platform. It serves as the main entry point for accessing the different modules and
for interacting with IRI messages. From this screen, users can easily navigate the
platform and perform the key actions described below:

    •  Left-side navigation menu (item 1 in figure 2): Gives access to the different
      modules of the platform through a simple icon-based menu (IRI dashboard,
       Referential, Creation of new IRIs, Reconciliation, Formal notices and penalties,
        settings, information, disconnection)

    •  Top filter bar (item 2 in figure 2): Allows users to refine the displayed
       information using dedicated criteria which depends on the information shown

    •  Right-Side detail panel (item 3 in figure 2): It shows detailed information for
       the selected information in a split-view format, organized into multiple sub-tabs.

6.2 IRI 01 management (Market participants &
registrars)

6.2.1 Overall Description


The GUI offers users a streamlined and intuitive way to create, validate, and submit an
IRI01 message directly within the IRI platform. This functionality is particularly useful for
institutions that do not use file transfers, or only use them partially, and prefer a guided,
visual workflow.

An IRI01 message is used to transmit information on final investors from the custodian
to the registrar on in some case to transmit the information from the registrar towards
the custodians. In the GUI, the creation of an IRI01 is divided into three separate
pages, each corresponding to one of the core sections of the message (Header,
Matriculation, and Restriction).

This step-by-step structure ensures that users complete the instruction in a clear and
logical order, while the GUI applies the rules defined in the Data Dictionary.

Detailed explanation of the three sections:

    •  Header (figure 1): it is the first section of IRI01. It contains the key functional
       information needed to identify the instruction and determine the type of action
       requested. This includes the operation type (conversion, portfolio transfer,
        registration after a trade, update), relevant dates, and the participant’s identifiers.
      These fields allow the platform and the registrar to process the instruction
        correctly. The GUI highlights mandatory fields and performs basic validations to
       help users avoid errors.

    •  Matriculation (Figure 2): the Matriculation section contains all information
       related to the final investor. This includes personal or legal details such as the
      name, address, postal code, and other identification elements depending on the
      framework. The GUI guides the user through these fields and ensures that
      mandatory information is provided. This section is essential, as it defines the
       investor to whom the registration relates.

6.5 Viewing and Processing Received IRI
 Messages (Registrar)


An IRI03 (or BRN03) message is used by the registrar to communicate to the market
participant sender the acceptance or refusal of an IRI previously submitted. It serves as
the formal response message in the instruction workflow and allows custodians to
immediately identify whether the registration request has been validated or requires
correction. This message closes the operational loop of the IRI process by providing the
official outcome of the instruction.

Unlike the IRI, which is composed of three separate sections (Header, Matriculation, and
Restriction), the IRI03 message contains a single section regrouping all the
information required to convey the decision of the registrar. The fields included in this
section are defined in the Message Dictionary and allow the platform to apply the
appropriate business rules.

As with the creation of an IRI, registrars have the ability to generate the response
(IRI03 only) directly via the GUI. In this case, the interface ensures the consistency
of the response, highlights mandatory fields, and supports basic validation to avoid input
errors. The user selects the IRI01 to be answered and completes the relevant response
elements in the dedicated section.

Based on the response, platform send back the related information to the Custodian
using an IRI04 message.

6.11 Formal Notices and Penalties

6.11.1 Description


Within the GUI, each movement subject to monitoring appears as an individual record
associated with a set of status indicators and counters. These elements allow users to
follow the progression of formal notices (“Mises en demeure”) and penalties over time.

When a participant fails to send an IRI01 within the required deadline, the platform
issues a formal notice and increments the corresponding counter. If the instruction
remains outstanding, a penalty is applied, followed by additional formal notices at
predefined intervals until the missing IRI01 is eventually submitted. The same
mechanism applies to registrars, both when they fail to send an IRI01 in due time and
when they do not respond to an IRI01 submitted by a market participant.
