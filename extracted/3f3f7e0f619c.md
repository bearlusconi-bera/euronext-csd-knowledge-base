    1.5. Messages Content and Structure


   Each message is identified by a three-digit numerical reference preceded by the acronym
   MT, which stands for ‘Message Type’. This identification does not adhere to any coding or
   standardised principles; hence, none of the three digits in the numerical reference hold
   any particular significance.

   Each message must conform to the following structure:

       • a heading, shared by all the messages circulating on the network

  1.6. Messages Conventions applied


The shared part of all the messages is composed of five blocks designated B1 to B5:

    ▪ B1: SENDER IDENTIFICATION (mandatory block)

    ▪ B2: TRANSACTION REFERENCE (mandatory block)

    ▪ B3: RECEIVER IDENTIFICATION (mandatory block)

    ▪ B4: TYPE OF SENDER (optional block)

    ▪ B5: TRANSACTION CODE (mandatory block).

How to compile these blocks is detailed in the corresponding sections in chapter 3 – ‘Field
Descriptions’.

The section detailing the application of messages is found in Chapter 2, titled ‘Messages’.

The content of these messages must adhere to the general guidelines outlined below.

1.6.1. Types of Controls Conducted


Euronext network validates messages based on and the transaction code (field B5).
Validation checks are performed field by field by PTCS, following what described in this
document.


1.6.1.1. Format Control

• Numerical Field:

    1. If optional, it must be numerical but can be filled entirely with zeros.

The refusal reason code will give the following reasons for refusing a transaction notice:

   •  Reasons linked to the transaction notice characteristics:
     -  Mandatory data not provided: the field corresponding to a mandatory item for the
       system was not filled in. This code is justified only when the network does not
       ensure existence controls;

     -   Invalid format: the data is not formatted as required (for example, alphabetical
        characters appear in a numerical field). This code is justified only when the
       network does not ensure format controls;

     -   Incorrect reference: the data no longer corresponds to the current state of
        reference table database (for example, change of security code) or the applicable
           tariff. This code is justified only when the reference table database is managed by
        the participants (not by the market system);

     -   Inconsistency with original order: the data is not compatible with the data initially

     -  Execution date invalid: the initial order indicated a deadline after which the order

       was generated for an order known as ‘fallen’. This notice should therefore be
        refused;
